Read-only deep audit scoped to `engine/ats_engine/*.py`, `docs/`, `prompts/`, `config/`, `engine/tests/`, and `.github/`. This report records findings only; it does not propose or apply fixes.

## Hata

- **Degenerate must-have input still fail-opens to full coverage.** The explicit empty-list case is handled, but a non-empty list containing only blank strings skips every term and falls through to `cov = 1.0` when `den == 0`; this avoids `ZeroDivisionError` but still creates a false-perfect coverage result for malformed caller input. **Kanıt:** `engine/ats_engine/scoring.py:136-157`.
- **ParseGate can influence Level 2 more than once.** Section selection calls `ats_match_score()` per section, then the combined CV is scored again with `ats_match_score()`, and both paths auto-compute `parse_gate` when the caller does not inject one; the docs also describe parse safety as a separate QA step. That makes parse noise affect section ranking, final L2 score, and QA signaling in the same flow. **Kanıt:** `engine/ats_engine/multilevel.py:175-185`, `engine/ats_engine/multilevel.py:254-289`, `engine/ats_engine/scoring.py:251-258`, `docs/10-sekiz-parca-skorlama.md:64-71`.
- **Shortened hash IDs leave a real collision budget in provenance-critical identifiers.** Artifact IDs and requirement IDs both truncate SHA-256 to 16 hex chars, while provenance docs describe a stronger SHA-256/locator/version chain. The risk is low, but the runtime ID budget is materially smaller than the documentation language suggests. **Kanıt:** `engine/ats_engine/ingestion.py:19-20`, `engine/ats_engine/job_requirements.py:84-86`, `docs/architecture/provenance-and-anti-hallucination.md:17-20`.

## Çelişki

- **“No universal target band” is the canonical rule, but legacy target-band markers still remain.** The canonical docs say target bands are not universal and should only exist inside a versioned evaluation profile, yet the scoring module still ships `75/85/90/50` threshold metadata and the English master prompt still calls out `>90%` as a stuffing signal. **Kanıt:** `docs/03-skorlama-matematigi.md:32-40`, `docs/decisions/ADR-001-evidence-first-v2.md:20-23`, `engine/ats_engine/scoring.py:42-45`, `prompts/master-prompt-EN.md:48-52`.
- **JD-parser conservatism and direct `score` CLI permissiveness do not enforce the same trust boundary.** `parse_jd()` refuses to promote body keywords to `must_have` and marks `none_detected` for review, but `ats-engine score` accepts arbitrary caller-supplied `--must` values and defaults missing `parse_gate` to `1.0` instead of the more conservative auto-parse path used by `report`/`diagnose`. **Kanıt:** `engine/ats_engine/jd_parser.py:260-340`, `engine/ats_engine/cli.py:80-94`, `engine/ats_engine/cli.py:165-171`, `engine/ats_engine/report.py:101-125`.
- **Deterministic/zero-dependency positioning coexists with optional semantic/model-driven behavior.** Multiple docs position the engine as deterministic and contract-first, but scoring still conditionally loads SBERT and the broader workflow docs/prompts still assume multi-model CV generation. The split is intentional, yet the repo still presents both narratives side by side. **Kanıt:** `engine/ats_engine/scoring.py:21`, `engine/ats_engine/scoring.py:72-93`, `docs/10-sekiz-parca-skorlama.md:22-35`, `prompts/master-prompt-TR.md:86-88`.

## Çakışma

- **The documented `H` formula and runtime clamping boundary are not identical under custom weights.** Docs define `H = LangGate × ParseGate × clamp(raw, 0, 1)`, while code computes `clamp(LangGate × ParseGate × RAW, 0, 1)`. With default normalized weights the difference is muted, but the public API does not constrain `alpha + beta + gamma` to `1`, so custom caller weights can make the documented and executed formulas diverge. **Kanıt:** `docs/11-uc-seviyeli-skorlama.md:9-12`, `engine/ats_engine/scoring.py:259-266`, `engine/ats_engine/scoring.py:335-336`.
- **L1 `tau` and L2 `kappa` are both score-shaping controls, but they are not calibrated against each other.** L1 is a hard pass/fail gate at `0.70`, while L2 recomputes score and then subtracts seam penalty `κ × (1 - dominant_ratio)`. That means L1 and L2 scores are not directly comparable even though both are framed around the same `H` family. **Kanıt:** `engine/ats_engine/multilevel.py:29-31`, `engine/ats_engine/multilevel.py:140-169`, `engine/ats_engine/multilevel.py:239-295`, `docs/11-uc-seviyeli-skorlama.md:29-34`, `docs/11-uc-seviyeli-skorlama.md:55-63`.
- **Parse safety acts both as a numeric multiplier and as a higher-level decision/gating signal.** The numeric diagnostic already multiplies by `Parse_gate`, while the decision layer and diagnostic tree also treat parse as a distinct top-level gate/root-cause branch. This is explainable, but it creates a collision between “score component” and “hard workflow gate” semantics. **Kanıt:** `engine/ats_engine/scoring.py:245-257`, `docs/decision_engine.md:8-16`, `docs/diagnostic_tree.md:13-18`.

## Örtüşme

- **Skill meaning is distributed across multiple lexical surfaces.** Canonical skill normalization lives in `skill_synonyms.json`/`lexicons.py`, domain detection uses domain-pack keywords, and prompts/docs still carry parallel keyword vocabularies and behavioral guidance. That increases maintenance overhead and raises the chance of partial drift between runtime matching and human-authored prompt language. **Kanıt:** `engine/ats_engine/lexicons.py:122-165`, `engine/ats_engine/domain_packs.py:76-128`, `engine/ats_engine/domain_packs.py:131-169`, `prompts/master-prompt-EN.md:62-69`, `prompts/master-prompt-TR.md:60-79`.
- **Tokenization and lexical overlap are not governed by a single contract everywhere.** `text.tokenize()` is the advertised shared tokenizer, yet `evidence_bank.find_support()` tokenizes with ad hoc regexes, `lexicons.jaccard()` uses whitespace splits, `domain_packs.detect_domain()` uses raw substring checks, and `cv_parser.parse_safety_score()` counts words with `split()`. These parallel token contracts can produce different overlap/count behavior on the same text. **Kanıt:** `engine/ats_engine/text.py:70-84`, `engine/ats_engine/evidence_bank.py:91-105`, `engine/ats_engine/lexicons.py:168-180`, `engine/ats_engine/domain_packs.py:141-163`, `engine/ats_engine/cv_parser.py:266-289`.
- **Evidence is scored twice with different lexical heuristics.** `report.build_report()` classifies gaps through `evidence_bank.find_support()` and also computes evidence recall via `completeness_guard.evidence_recall()`. Both analyze the same evidence corpus, but one uses overlap/Jaccard on claims and the other uses token-set recall against the full CV, so “support” and “recall” can drift for the same underlying fact set. **Kanıt:** `engine/ats_engine/report.py:124-127`, `engine/ats_engine/report.py:210-215`, `engine/ats_engine/evidence_bank.py:86-109`, `engine/ats_engine/completeness_guard.py:41-80`.

## Eksik

- **No `llms.txt` surface was found, and FAQ/HowTo-style discoverability artifacts are absent.** The repo exposes README quick-start material, but the audit scan found no `llms.txt`, no FAQ page, no HowTo schema/article surface, and no `FAQPage`/`HowTo` markers. **Kanıt:** `README.md:23-46`.
- **Structured observability is still thin.** The codebase now uses module loggers in a few places, but there is no visible centralized logging config, correlation ID strategy, JSONL sink, or failure-artifact upload path for the main quality/test/package jobs; only the historical-baseline job uploads artifacts. **Kanıt:** `engine/ats_engine/scoring.py:26-37`, `engine/ats_engine/report.py:20-41`, `.github/workflows/test.yml:15-83`, `.github/workflows/test.yml:94-114`.
- **There is no machine-readable provenance manifest in the main report payload.** The output template explicitly models provenance and synthesis change sets, and the provenance architecture doc describes locator/hash/version chains, but `build_report()` emits `keywords/analysis/summary/synthesis/match_score/gap_analysis/skill_count_table/qa_checks/decision_report` without a dedicated per-claim provenance manifest. **Kanıt:** `prompts/output-fields-template.md:28-49`, `docs/architecture/provenance-and-anti-hallucination.md:17-24`, `engine/ats_engine/report.py:250-273`.

## Aksaklık

- **`tr_lower` is “English-I-safe,” not truly acronym-preserving, and domain-specific acronyms remain under-tested.** The implementation intentionally lowercases acronyms, and the regression suite proves this for `INCOTERMS/ERP/SAP/ISO`; however, domain-specific forms such as `TIR` are not covered directly even though uppercase trade acronyms such as `GTIP` are embedded in domain data and parser logic. The current naming overpromises more than the tests guarantee. **Kanıt:** `engine/ats_engine/text.py:23-41`, `engine/tests/test_core.py:562-579`, `engine/ats_engine/jd_parser.py:196-199`, `engine/ats_engine/domain_pack_data/foreign-trade-logistics/keywords_tr.json:7`.
- **Action-verb breadth is narrower than some docs still claim.** Runtime metadata and tests agree on `260` action verbs, while a legacy doc still says “700+ aktif eylem fiili.” This is a documentation/runtime drift and also a genuine breadth limit for a bilingual resume-writing corpus. **Kanıt:** `engine/ats_engine/data/action_verbs.json:6-7`, `engine/tests/test_core.py:668-680`, `docs/05-grammarly-entegrasyonu.md:21`.
- **Domain coverage is intentionally shallow today.** The active user config points to a single primary pack, and module-status docs explicitly label domain packs as one-domain only. That keeps the engine explainable, but it limits transfer outside foreign trade/logistics. **Kanıt:** `config/user_profile.yaml:51-53`, `docs/module_status.md:20-29`.
- **Test quantity is stronger than the old “43 tests” narrative, but coverage shape is still narrow in the exact audit areas requested here.** The current tree contains broad unit/regression/contract coverage, yet there are no direct regressions for short-hash collision behavior, `llms.txt`/FAQ/GEO surfaces, or L1/L2 calibration consistency. The maturity doc’s own target bar remains higher than the repo’s current state. **Kanıt:** `docs/maturity_model.md:24-28`, `docs/maturity_model.md:40-48`, `engine/tests/test_regressions.py:28-140`, `engine/tests/test_matching_cascade.py:15-118`.

## Geliştirme Fırsatı

- **Profile-specific market bands can be added without reintroducing a universal score claim.** The config already states that thresholds must be profile-bound and role/market-versioned; that creates a natural extension point for region-specific diagnostic bands such as US vs CN without breaking the canonical “no universal target band” rule. **Kanıt:** `config/user_profile.yaml:33-44`, `docs/03-skorlama-matematigi.md:32-35`, `docs/architecture/system-overview.md:25-30`.
- **An Ads-style quality view is conceptually available but not yet first-class.** The repo already has separate parse, lexical/coverage, evidence/trust, and calibration branches; these could be presented as an explicit “quality score” decomposition rather than remaining scattered across `match_score`, `decision_report`, QA checks, and diagnostic docs. **Kanıt:** `docs/diagnostic_tree.md:13-50`, `docs/decision_engine.md:8-16`, `engine/ats_engine/report.py:250-273`.
- **The maturity model exists as policy but is not yet wired into runtime behavior.** `maturity_model.md` already defines stage-specific expectations, yet those stages do not drive configuration, gating, or reporting outputs. That makes the model informative for humans but inert for the engine. **Kanıt:** `docs/maturity_model.md:10-35`, `docs/maturity_model.md:36-56`.
- **The diagnostic tree is documented, but not emitted as a dedicated structured artifact.** There is already a seven-branch diagnosis concept and a `diagnose` CLI, but the main report payload does not serialize a branch-by-branch causal tree that could be consumed by downstream GEO/AEO tooling or dashboards. **Kanıt:** `docs/diagnostic_tree.md:1-4`, `docs/diagnostic_tree.md:53-72`, `engine/ats_engine/report.py:250-273`.
